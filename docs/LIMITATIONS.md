# Ограничения и план развития

## Где подход ошибается

Детектор построен на правилах, словарях и морфологии. Он быстрый и предсказуемый, но знает
только те форматы, которые описаны правилами. Самая честная цифра обобщения: половина второго
слепого набора, которую мы не открывали до замера, дала span similarity 0,972 и 0,9% ложных
срабатываний на ловушках. На первом слепом наборе после правок 0,994, но это уже подгонка под
известные примеры. На скрытом датасете оргов ожидаем результат около 0,97.

Известные пропуски, которые мы сознательно не закрывали:

| Случай | Почему пропуск | Что нужно |
|---|---|---|
| ФИО, которых нет в словарях, без слова-триггера: редкие иностранные имена | словари и pymorphy3 не знают слово, структура не спасает | лёгкая NER-модель вторым проходом на тексты без найденного ФИО |
| Таблица Markdown, где серия и номер паспорта в разных колонках | правило видит строку, а не столбец | разбор структуры таблицы: заголовок колонки как метка |
| Адрес без триггера: «привезёт карту на Профсоюзную, 84» | без слова «адрес» или типа улицы нет контекста | геословарь улиц крупных городов |
| Реплика диалога, где метка на одной строке, а значение на следующей | окно контекста не переходит через перевод строки, иначе растут ложные срабатывания | контекст на уровне реплик диалога |
| «Красный проспект» как название улицы целиком | маскируется «Красный», тип улицы остаётся | для оценки оргов это близко к правилам маски, для смысла не критично |

Ложные срабатывания на ловушках сведены к нулю на нашем наборе, но публичные персоны
определяются справочником и маркерами рядом. Известный человек без маркера и вне справочника
будет замаскирован как клиент. Для защиты данных эта ошибка дешевле, чем пропуск.

## Ограничения восстановления после LLM

Позиционное восстановление в `/process` точное всегда: маска возвращается без изменений.
Восстановление ответа LLM по токенам зависит от модели. Модуль просит её в системном сообщении
сохранять метки дословно. Если модель исказит метку («[ФИО 1]», «ФИО_1»), значение останется
закрытым: данные не утекут, но клиент увидит метку вместо имени.

В режиме `synthetic` модель может просклонять подставное имя: «Морозову Виктору» вместо
«Морозов Виктор». Склонённая форма не найдётся в таблице соответствий и останется подставной.
Для ответов, которые уходят клиенту, надёжнее `placeholder`.

## Эксплуатация

| Ограничение | Последствие |
|---|---|
| Без `REDIS_URL` соответствия живут в памяти воркера | при нескольких воркерах демаска может попасть в другой процесс; для прода Redis обязателен |
| Без `VAULT_KEY` ключ шифрования создаётся в самом Redis | удобно для демо, но ключ лежит рядом с данными; для прода ключ задаётся явно, лучше из секрет-хранилища |
| Потоковый режим `stream: true` в LLM-прокси не поддержан | ответ 400 `stream_not_supported` |
| mTLS между системами и модулем не настроен | системы различаются по ключу в заголовке; mTLS ставится на уровне ingress |
| Изображения и OCR не поддерживаются | из сообщения с картинками в LLM уходит только замаскированная текстовая часть, картинки отбрасываются |
| TPS считается оценкой: символы / 3,5 | точное число токенов даёт только токенизатор конкретной модели |
| Нагрузка мерилась на одном хосте с генератором | цифры на выделенном стенде не проверены |
| Очень плотный длинный текст | 360 тыс. символов, где ПДн в каждой строке, обрабатываются около 16 с; обычный длинный текст того же размера около 4 с |

## План развития

1. **Второй проход NER на подозрительных текстах.** Лёгкая модель запускается только там, где
   правила не нашли ФИО, а в тексте есть слова с заглавной буквы вне начала предложения.
   Цель: закрыть редкие имена, не тратя 8 мс на каждый запрос.
2. **Разбор структуры.** Таблицы Markdown и CSV, JSON с ключами, диалоги по репликам: метка
   берётся из заголовка колонки, ключа или предыдущей реплики.
3. **Потоковый LLM-прокси.** SSE с буфером на границе токена: метка `[ФИО_1]` не должна
   разрываться между чанками при демаскировании.
4. **Эксплуатация в банке.** Ключ шифрования из Vault или HSM, mTLS на ingress, ротация ключей
   систем через админ-API, аудит-лог действий администратора.
5. **Контур качества.** Скрытые наборы от команд, которые пользуются модулем, ночной прогон
   `tools/eval.py` с порогами, отчёт о новых форматах, которые правила пропустили.
