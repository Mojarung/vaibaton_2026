# Архитектура

## Схема

```
                         ┌──────────────────────── Контур (granian, N воркеров) ────────────────────────┐
Система-потребитель ──►  │ граница: request id, лимиты 413/429, аутентификация системы, политика        │
  X-System-Id            │    │                                                                         │
  X-Api-Key              │    ▼                                                                         │
                         │ идентификация: YAML-правила ► ФИО ► цепочки адреса ► разрешение пересечений │
                         │    │                                                                         │
                         │    ▼                                                                         │
                         │ маскирование: placeholder | redact | stars | partial | synthetic             │──► LLM (AlfaGen,
                         │    │                          соответствия ─► Redis, AES-256-GCM             │    OpenAI API)
                         │    ▼                                                                         │       │
                         │ демаскирование: по позициям (маска не менялась) или по токенам (ответ LLM)   │◄──────┘
Система-потребитель ◄──  │ лог request.done (типы ПДн и тайминги, без значений), метрики Prometheus    │
                         └──────────────────────────────────────────────────────────────────────────────┘
```

Модуль работает как прокси в трёх режимах. `POST /process` реализует контракт автопроверки,
`/v1/mask` и `/v1/unmask` нужны системам, которые сами ходят в LLM, а `/v1/chat/completions`
принимает OpenAI-запрос, маскирует сообщения, вызывает модель и демаскирует ответ.

## Почему без нейросетевого NER

Бюджет при 1000 RPS на 4 CPU около 4 мс CPU на запрос, и большую его часть съедают HTTP и
хранилище. Лёгкие русские NER-модели тратят на короткий текст единицы миллисекунд и больше, а
ФИО в нижнем регистре и с инициалами находят хуже правил со словарями. Поэтому детектор
построен на правилах, словарях и морфологии pymorphy3. Средняя цена детекции около 1 мс на
текст, качество на отложенной половине второго слепого набора 0,972.

## Конвейер детекции

Код в `pii_guard/core`. Текст длиннее 6000 символов режется на куски по ближайшему сильному
разделителю: абзац, строка, конец предложения. Куски обрабатываются независимо, спаны
сдвигаются обратно. Так регулярные выражения не упираются в таймаут на тексте в 100 тыс. токенов.

1. **YAML-правила** (`detect_rules.py`, 87 правил в `config/rules`). У каждого правила есть
   префильтр: подстроки (`requires_any`) и минимум цифр (`min_digits`). Правило, которому нечего
   искать в тексте, не запускается.
   Кандидат проходит валидаторы (Луна для карт, контрольные суммы ИНН и СНИЛС, правдоподобная
   дата рождения), негативный контекст («горячая линия», «код ошибки», «ПАО») и проверку по
   словарю. Повторяющиеся группы дают несколько значений за одно совпадение: «PIN то ли 1357,
   то ли 7531».
2. **ФИО** (`detect_person.py`). Словари natasha (7,6 тыс. имён, 182 тыс. фамилий) и pymorphy3
   оценивают каждое слово как имя, фамилию или отчество в любом падеже и регистре. Группа из
   двух-трёх соседних слов собирается в ФИО по структуре: «Фамилия Имя Отчество», «Имя Отчество»,
   инициалы с фамилией, латиница. Одиночное слово маскируется только после триггера («клиент»,
   «ФИО:»). Публичная персона определяется ближайшим маркером («поэт», «роман», «улица имени»)
   и справочником.
3. **Цепочки адреса и места рождения** (`detect_address.py`). После триггера («адрес
   регистрации», «проживает», «родилась в») конечный автомат идёт по токенам и маскирует
   значения компонентов: город, улицу, дом, квартиру. Служебные слова «г.», «ул.», «д.»
   остаются открытыми, потому что метрика оргов штрафует их маскирование. Адрес рядом с маркером
   организации («отделение банка», «офис») не маскируется.
4. **Разрешение пересечений** (`resolve.py`). Короткий спан внутри длинного надёжного спана
   удаляется: «К.» в «Данилова К.О.» не литера корпуса. Остальные пересечения решает приоритет,
   затем длина. Соседние спаны одного типа склеиваются: «4509» и «123456» дают одно значение.
5. **Дополнительные виды текста.** Детектор ещё раз проходит по компактному виду
   («5536 - 9137 - 5000» склеивается в «5536-9137-5000») и по виду, где числительные словами
   заменены цифрами («восемь девятьсот шестнадцать ...»). Найденные спаны переносятся обратно на
   исходный текст по таблице смещений.
6. **Одиночное значение.** Если ничего не найдено, а весь payload короткий, тип угадывается по
   форме: 16 цифр с валидным Луном дают карту, «Петров Пётр Петрович» даёт ФИО.
7. **Комбо-правила политики.** PIN без карты рядом удаляется, если система так настроена.

## Маскирование и демаскирование

`pii_guard/mask`. Одинаковое значение в одном запросе получает один и тот же токен, разные
значения получают разные номера: `[ФИО_1]`, `[ФИО_2]`. Режим выбирается политикой системы и
может отличаться по типам.

| Режим | Пример для «4276 3800 1234 5678» | Обратимость |
|---|---|---|
| `placeholder` | `[НОМЕР_КАРТЫ_1]` | да |
| `redact` | `[НОМЕР_КАРТЫ]` | нет |
| `stars` | `**** **** **** ****` | нет |
| `partial` | `4276********5678` | нет |
| `synthetic` | другой номер той же длины и формата с верной контрольной цифрой | да |

Демаскирование работает двумя способами. Если маска вернулась без изменений (контракт
`/process`), значения вставляются по сохранённым позициям, и результат совпадает с оригиналом
побайтно. Если текст переписала LLM, модуль ищет токены в ответе и заменяет каждое вхождение,
в каком бы порядке и количестве токены ни встретились.

## Хранение соответствий

`pii_guard/store/vault.py`. Запись о паре маска/оригинал лежит в Redis под адресом
`pii:<пространство>:<система>:<HMAC(идентификатора)>`. Содержимое шифруется AES-256-GCM, адрес записи служит
associated data, поэтому запись нельзя переложить под другой ключ. В записи хранятся HMAC
исходного текста и маски, маска, позиции значений и словарь токенов.

Идемпотентность `/process` устроена так. Запрос читает запись по адресу. Если пришёл тот же
исходник, это повтор маски, и возвращается сохранённая маска. Если пришла сохранённая маска или
текст с её токенами, это демаска. Новая запись пишется через `SET NX`: два параллельных повтора
одного запроса не создадут разные маски.

Срок хранения задаёт политика (`ttl_seconds`, по умолчанию 24 часа). Redis работает без
персистентности (`--save ""`, `--appendonly no`) с `maxmemory 1gb` и вытеснением по TTL.
При недоступности Redis воркер переходит на память процесса и считает деградацию в метриках.

## Системы-потребители и политики

`pii_guard/policy`. `config/systems.yaml` описывает системы, `SystemRegistry` проверяет файл
схемой Pydantic и собирает для каждой системы готовые `DetectionOptions`. Ключ системы берётся из
переменной окружения, имя которой указано в `api_key_env`, сравнение идёт через
`hmac.compare_digest`. Каждый воркер следит за `config/` через watchfiles и перечитывает
политики, правила и словари без перезапуска. Ошибка в YAML пишется в лог, а воркер продолжает
работать со старой версией.

## Производительность

`POST /process` обходит роутинг FastAPI: `BoundaryMiddleware` узнаёт путь и вызывает обработчик
напрямую как ASGI-приложение (`pii_guard/api/fast_process.py`). Сервер granian в режиме `mt` с uvloop, воркеров столько же, сколько
CPU. Живая статистика `/stats` собирается по всем воркерам через Redis, метрики Prometheus
работают в multiprocess-режиме. Замеры в [PERFORMANCE.md](PERFORMANCE.md).

## Безопасность

| Угроза | Что сделано |
|---|---|
| ПДн в логах | лог пишет только типы, количества и тайминги; structlog-процессор заменяет на `<redacted>` поля `payload`, `text`, `original`, `masked`, `result`, `content`, `messages`, если они случайно попадут в событие; тест `tests/test_no_leaks.py` проверяет лог и метрики |
| ПДн в ответах об ошибках | обработчик ошибок валидации отдаёт только имена полей, без присланных значений |
| Чтение соответствий из Redis | AES-256-GCM, адрес записи как associated data, ключ из `VAULT_KEY` |
| Чужая система демаскирует данные | запись привязана к системе в адресе, демаскирование выключается политикой |
| Перегрузка | лимит одновременных запросов на воркер (429 с `Retry-After`), лимиты тела и длины текста (413) |
| Секреты в репозитории | ключи только в `.env`, который в `.gitignore`; в репозитории `.env.example` с заглушками |
| Сбой детектора | весь текст закрывается меткой `[СКРЫТО_1]`, в LLM ничего не уходит открытым |

## Структура кода

```
pii_guard/
  api/        FastAPI-приложение, быстрый путь /process, middleware, админка, LLM-прокси
  core/       детекция: правила, ФИО, адреса, разрешение пересечений, словари, морфология
  mask/       маскирование, синтетика, восстановление
  policy/     схема политики и реестр систем с горячей перезагрузкой
  store/      хранилище соответствий: Redis, AES-GCM, запасной вариант в памяти
  observe/    structlog, метрики Prometheus, живая статистика
  llm/        клиент OpenAI-совместимого API с демо-режимом
  quality/    метрики качества для датасетов
config/       systems.yaml, rules/*.yaml, context.yaml, address.yaml, gazetteers/
datasets/     слепые наборы и их генераторы
tools/        генерация вариаций, оценка качества, бенчмарки
load/         сценарии k6
deploy/       Prometheus и Grafana
```
